# AI Music Cut

**繁體中文** · [English](README.en.md)

> ☕ 這個工具免費且開源。如果幫上忙，可以 [請我喝杯咖啡](#贊助開源)。

AI Podcast / 音訊智慧剪輯桌面工具（Tauri 2 + React 18），也有 CLI。丟進一段錄音，它會：

1. **剪贅字與口吃**：嗯／呃／那個／就是／我我我……以及講到一半重講的片段，但**以自然順暢為最高原則**——句首的「然後」、有節奏感的語助詞會保留，不是全剪。規則層先提候選，Claude 再逐段判讀自然度。
2. **音量平衡**：逐段 BS.1770 量測 → 增益規劃（±12 dB、峰值守門、平滑）→ EBU R128 loudnorm 兩趟，成品落在目標響度（預設 −16 LUFS）。
3. **含糊 / 離題 / 「再來一次」段落給建議**：偵測到但不自動剪，列成建議讓你逐一接受或拒絕。
4. **人也能剪，不只 AI**：開檔就有波形（不必先分析），「選取」工具拖一段就能播放（可循環）、剪掉、只保留、靜音、淡入淡出、增益；候選色塊可拉邊界、雙擊剪 ↔ 不剪；逐字稿 Shift+點選範圍、雙擊字直接剪。Wave Editor 式右鍵選單。
5. **剪輯工具組（Final Cut 式）**：`B` 刀片在播放線切一刀（切點本身不動聲音，只是立一個抓得住的把手，右鍵可以在這裡**插入 200 / 500 / 1000 ms 留白**當段落呼吸）；`T` 修剪工具在每個接縫長出把手 —— 拖**中間**是捲動（roll，接縫左右一起動，成品總長不變），拖**兩側**是漣漪（ripple，後面整串跟著位移）；`N` 統一吸附（接縫 / 句界 / 字界 / 拍點，容差跟著縮放走）；`Shift+Delete` 提起（lift）＝留白靜音不關洞，拿掉咳嗽但保留節奏。
   > 人親手拖出來的邊界會**照著用**：不再做 ±30 ms 的能量最低點搜尋、也不回填呼吸（那兩段是為了讓 AI 提的候選落在安靜處）。只保留 ±3 ms 的零交越微調擋 click。所以捲動修剪真的不會改變成品長度。
6. **轉盤與精準修剪**：`J` / `K` / `L` 是真的轉盤 —— 連按加速 1x → 2x → 4x，**J 與 L 互相抵銷**（衝過頭反手點一下是降速，不是立刻倒帶），按住 `K` 再點是 0.5x 慢速；倒退只移動播放線（`<audio>` 放不出反向音訊，UI 會標「靜音」）。`I` / `O` 標入出點，`Alt+←/→` 微調 ±10 ms（加 `Shift` 是 ±1 ms）。右鍵接縫 →「在這裡精準修剪」打開**精準修剪器**：上排是來源（被剪掉的打斜線）、下排是剪完真正會聽到的接法，同一個 ms/px 比例並排，接縫附近的字疊在波形上，所以「吃掉半個字」用看的就看得出來；可以只聽左尾 / 只聽右頭、逐 1 ms 修，`[` `]` 在接縫之間跳。
7. **標記、時間軸索引、章節匯出**：`M` 下標記、`Shift+M` 下章節、`Alt+M` 下待辦、`Alt+[` `Alt+]` 在標記之間跳（波形右鍵與索引分頁的「在播放線新增」也都做得到，不用記快捷鍵）；圖釘畫在時間尺上可以拖、可以右鍵改類型。右側「索引」分頁是 Final Cut 的 Timeline Index —— 把整條時間軸攤成一份可搜尋、可篩選的清單（章節 / 標記 / 待辦 / 接縫 / 效果），點一下就跳過去，章節標題直接在這裡改。**章節會寫進成品檔案**：mp3 得到 ID3 CHAP、m4a 得到 QuickTime 章節（Apple Podcasts / Spotify 讀得到），時間會自動從「來源」換算成「剪完之後」的位置。待辦可以打勾，未完成的數量顯示在分頁上。
8. **配樂 / 音效軌與自動閃避**：波形下緣多了兩條 lane。在波形上右鍵就能把媒體清單裡的檔案放成**配樂**（預設 −18 dB、兩秒進出）或**音效**，拖曳移動、拖邊界修剪。右鍵配樂 →「讓配樂在人聲下自動閃避」會依人聲區間算出**看得見也拖得動的音量控制點**（人聲開口前先壓下去、講完再回來），而不是丟給壓縮器猜——曲線就畫在音樂條上，**每個控制點都能拖**：上下改音量、左右改時間、`Alt`+點加一個、右鍵移除。位置釘在**成品時間**：之後再多剪掉幾個贅字，音樂不會跟著往前跑。選好一段之後，選取列的分享鈕可以**只輸出這一段**（社群短片用）：剪輯、配樂與閃避全部照舊，只是頭尾被夾掉，專案本身完全不動。輸出時可以勾「同時輸出分軌」，人聲一個檔、配樂與音效一個檔（三個檔共用同一組響度量測，所以各軌之間的相對音量跟完整混音一致）。片尾曲可以拖到**最後一句話之後**，成品會跟著變長（不會在講完的那一刻被硬切）。**放完直接按播放就聽得到**（配樂跟著播放線走，跳播、轉盤變速都跟得上）；成品的精準混音在輸出那一趟做，插在 loudnorm 之前，所以目標響度算的是你實際聽到的那一份。
9. **多麥克風同步（Final Cut 的 Synchronize Clips）**：一人一軌的遠端錄音，各自按下錄音會差好幾秒。工具列「同步麥克風」→ 勾選各軌（第一個是基準）→ 自動用**兩軌都聽得到的講話節奏**（能量包絡，不是波形）對齊，列出各軌位移與信心，確認後併成一個 `_synced.wav` 繼續剪。原始檔案不會被動到；信心偏低時會明講「可能沒對上」而不是硬合併。
   合併時可以順便**降低串音**（別人講話漏進這支麥的聲音，合起來會讓同一句聽到兩次：一次清楚、一次糊的）。門檻是從**每一軌自己的能量分布量出來**的，不是寫死的數字 —— 每支麥的增益、距離、房間都不一樣，寫死一定有人被切掉氣音、有人完全沒作用。本來就沒有安靜段的軌會自動跳過。
10. **剪音樂：節拍格線與貼齊**：開檔就從波形能量自動抓 BPM（自相關），時間軸畫出拍線與小節線，選取自動吸附到拍點——剪在拍子上，接起來才不會破。**AI 抓錯也能一鍵修**：÷2 / ×2 換半拍倍拍、把播放位置設成小節首拍、跟著音樂敲 3 下抓速度。
11. **自動精華片段**：工具列「精華片段」→ 選 15 / 30 / 60 / 90 秒，AI 依能量與律動挑出最像副歌的一段（有拍網格時起訖貼齊小節），可試聽後「只選起來」自己微調或「只保留這段」（自動加淡入淡出）。
12. **AI 配樂（ACE-Step）**：描述風格就生出純器樂 BGM，長度自動帶入目前選取、BPM 帶入偵測到的拍速，生好直接加進媒體清單就能剪、貼齊拍點、輸出。
13. **曲風轉換**：在波形上選一段 → 右鍵「改成另一種曲風…」或選取列的調色盤鈕 → 描述目標曲風（Lo-fi 化 / 原聲吉他 / 電影感 / 8-bit…），用選取那段當參考做 audio2audio；貼近度滑桿決定「保留原旋律」還是「自由發揮」。
14. **去人聲 / 分軌**：一鍵把人聲與伴奏（或 4 軌）分開，伴奏軌就是去人聲版本，可以接著剪。
15. **逐字稿搜尋與批次剪除（Descript 式的文字剪輯）**：`Ctrl+F` 在逐字稿裡找字 —— 比對忽略標點與空白，所以「那個那個」找得到「那個，那個」，也可以跨句。命中的字畫上底色、`Enter` 逐個跳，按「全部剪掉（N）」把整集的它一次處理掉，**一次 undo 就全部還原**。搜尋列還會列出這一集真正出現的口頭禪（`呃 ×23` 這種 chip，點一下就填進去）—— 規則層認的是聲學加詞表，認不出你自己的口頭禪。
   > 剪掉「某一句話」逐字稿本來就做得到（Shift 點字選一段 → Delete）。這裡解的是**重複**的那一種：整集 23 個「呃」一個一個剪，是這套工具最累的操作。

15b. **贅字管理（依詞整群處理）**：一集 57 分鐘會提出上千筆贅字候選，逐筆審是審不完的 —— 但它們其實只有二三十個「詞」：「然後」四百次、「就是」兩百次、「對」一百次。工具列「贅字管理」把它們**按詞攤成一張表**（次數 / 已剪 / 待決 / 不剪 / 可省多少），一列一鍵「全剪」或「全留」。
   另一個分頁是**跨集有效的個人詞表**：每個主持人的口頭禪都不一樣，內建那份是通用的，你的疊在上面（一定剪 / 看語境 / 永不剪）。只存你動過的那幾個詞 —— 全部存下來的話，之後改進了內建詞表，你會被永遠凍在舊版本而且完全無感。Whisper 會把「我跟你講」拆成四個 token，所以自訂多字詞是一路接回來比對的（中間有 >200 ms 停頓就不算同一個詞）。
   > 改詞表不會自動改變已經算好的候選（候選是分析當下算的），所以有一顆明確的「套用到本集（重跑規則）」，並在改過之後標示出來。這件事不該讓人用猜的。

   **詞表會從你的做法自己長出來。** 每一集你都在對同一批詞做同一組判斷 —— 這件事應該只做一次。
   「贅字管理」底下有一顆「記住我這一集的 N 個判斷」，把**你親手做過的裁決**收起來（一集一筆，
   同一集重按是覆蓋不是累加，最多留 20 集）。累積幾集之後，「我的詞表」分頁會直接建議：
   「『欸都』你剪了 34 次、留了 1 次 → 設成一律剪」、「『然後』內建詞表會剪，但你留了 22 次 → 設成永不剪」。
   > **只算你親手做的**（origin = user）。自動剪掉的、AI 判讀的都不算 —— 把它們算進來就變成
   > 「規則層說要剪 → 學到要剪 → 更確定要剪」的自我循環，學不到任何新東西，只會把規則層本來就有的
   > 偏見放大成你的詞表。
   > 證據不夠（少於 5 筆）或意見不一面倒（低於 9 成）的詞**不會**出現：那些本來就該看語境。
   > 內建詞表已經會剪、你也一直在剪的詞也不建議 —— 設了對你沒有任何差別，只是多一條要維護的規則。
   > 反過來「內建會剪、但你每次都留著」是最值得建議的，那正是你的節目跟通用詞表不一樣的地方。
   > **建議永遠只是建議**：按了才改詞表，而詞表只影響下一次分析要不要提出這個詞，
   > 不會動到任何已經做好的剪輯決策。地端 claude 也有這兩支工具（`learn_filler_decisions` / `suggest_filler_rules`）。

15c. **領域詞（讓辨識器聽得對）**：人名、產品名、公司名、技術術語 —— 辨識器聽不出來的那些。設定 → 逐字稿 → 領域詞「維護」：晶片式增刪、批次貼上、去重（忽略大小寫但保留你第一次的寫法）、字元數與軟上限提醒。
   真正讓它有用的是**從這一集的低信心字推薦**：沒有人憑空想得起來要加哪些字，但看到「『Tauri』被聽成三種東西、信心 0.2」就知道要加了。推薦會排除贅字 —— 「我覺得」信心低是因為講得含糊，不是辨識器不認得它，加進去只會叫它更用力去聽一個等一下要剪掉的詞。
   > **領域詞跟贅字管理是相反的兩件事**：領域詞在辨識**之前**（請聽對這幾個字），贅字詞表在辨識**之後**（這幾個字要剪掉）。

16. **滑過就聽得到（skimming）**：`Shift+S` 打開之後，滑鼠在波形上移動就會聽到游標底下那一小段（Final Cut 的 audio skimming）。找「我剛剛那句話在哪」比拖播放線快得多。預設關著 —— 滑鼠經過就出聲要自己同意。正在播放時會自動讓開，不會兩個聲音疊在一起。

17. **精華合輯（把散落的好段落串成一支預告）**：一集剪完之後要丟社群的，通常不是連續的 60 秒，而是散在各處的三五句。在波形上選一段 → 動作列的星號加進「精華片段」→ 工具列「精華合輯」清單裡可以逐段試聽、命名、移除 → 一鍵輸出。段落之間自動交越 120 ms（兩邊在原本的錄音裡毫無關係，直接對接會很突兀），重疊的段落自動合併（不然同一句會聽到兩次），頭尾自動淡進淡出（預告一定是從句子中間開始、句子中間結束，不淡就是硬切進一個字的中段）。可以挑一首**墊樂**鋪在整支預告底下（−22 dB，頭尾淡進淡出）。專案完全不動；合輯不寫章節。

18. **修聲（去隆隆 / 降噪 / 齒音）**：工具列「修聲」。**去隆隆**是 80 Hz 高通 —— 桌子撞擊、冷氣、腳步都在這之下，人聲基頻最低約 85 Hz，所以幾乎零代價，建議值一律開著。**降噪**先量這份錄音「安靜的時候有多吵」再決定要減多少；底噪已經低於 −58 dBFS 就不建議做（再減只會吃掉語音尾音），上限 18 dB（過量會在安靜處產生水聲）。**齒音預設不開** —— 波形分析只有能量包絡、沒有頻譜，沒有任何量測依據可以說「這支麥克風齒音重」，所以讓你 A/B 聽過再開。整個對話框繞著 A/B 試聽設計：同一段、同一個位置算出原始與修聲後兩份，來回聽。
   > 修聲套在**響度正規化之前**，而且**量測與編碼兩趟都套**。loudnorm 走 `linear=true`，pass 1 量到的數字直接決定 pass 2 的增益；只在編碼那趟修聲的話，量的是沒修過的響度、套的是修過的訊號，成品會整體偏低。實測 12 秒片段：噪音底 −23.7 → −78.3 dB，RMS 只動 0.25 dB。

19. **節目筆記（show notes）**：剪完之後按工具列的「節目筆記」，地端 claude 讀這一集寫出摘要、章節、值得引用的句子與關鍵字，可以直接複製 Markdown 或存成 `.md` 貼到部落格 / RSS，章節也能一鍵寫成標記（於是會跟著寫進成品檔案）。產好的筆記存進專案檔，關掉再開不用重跑（重產一次要 claude 讀完整集）。
   > **時間戳是成品時間，不是逐字稿時間**。逐字稿在來源時間軸上，中間隔著整份 EDL —— 剪掉 20 個贅字之後，來源 12:30 那句話在成品裡是 12:11，剪愈多錯愈遠而且錯得很安靜。所以餵給 claude 的素材先換算好，它回來的時間戳再對節目長度驗一次（看不懂的、超出長度的、沒有遞增的一律丟掉 —— 寧可少一個章節，也不要讓聽眾按下去跳到空氣）。被剪掉的句子根本不會餵進去。

20. **輸出驗收（人機協作的最後一關）**：**音訊比對**（純本機）把成品每一段的波形包絡跟來源做正規化互相關，抓出接錯段或位置偏移；成品混了配樂時會自動改成**只比對位置**（多了音樂，包絡本來就不一樣，硬比波形相似度會對一個好成品報假警報）；有逐字稿時再加上 **ASR 逐字比對**（重新轉寫成品，標出漏字、該剪沒剪、可疑接縫），每筆都能「聽」或「去修」。
21. **AI 助手（Claude Code 式工具迴圈）**：本機 `claude` CLI 透過 App 內建的 MCP server 直接操作剪輯決策——「把 10 分鐘後的『就是』都剪掉，但句首的留著」。49 支工具涵蓋決策、接縫與修剪（`list_seams` / `blade_at` / `trim_seam` / `insert_pause` / `set_selection` / `lift_selection` / `add_effect`）、逐字稿（`find_text` / `cut_text`）、標記與章節、配樂與閃避、多麥同步、修聲（`get_cleanup` / `set_cleanup`）、精華片段（`list_highlights` / `add_highlight`）、節目筆記（`write_show_notes` / `get_show_notes`）、講者（`list_speakers` / `assign_speaker` / `rename_speaker` / `cut_fillers_by_speaker`）、字幕與分割（`export_captions` / `list_split_parts`）、響度輪廓（`get_loudness_profile` —— 助手聽不到聲音，這支讓它看得到）、交付前檢查（`get_preflight` —— 回答「可以輸出了嗎、還缺什麼」，含聲音體檢：削波 / 音量突變 / 直流偏移 / 長空白，各帶時間點）、贅字詞表學習（`learn_filler_decisions` / `suggest_filler_rules`）、替代 take（`list_takes` / `keep_take`），所以也接得住「把來賓的口頭禪都剪掉、主持人的留著」、「產一份帶講者名字的 SRT」或「在 12:30 切一刀，接縫往左推 200 毫秒」或「看看底噪要不要修，順便把整集的口頭禪剪掉」。

22. **批次處理（多集一次跑完）**：一個週更的節目手上常常同時有好幾集（補錄的、上週沒剪完的、分段錄的）。工具列「批次處理」勾選要跑的集數與步驟（分析 → 一鍵智慧剪輯 → AI 判讀 → 輸出），跑完列出每一集省了多少、輸出在哪、哪一步被跳過。
   **一次只跑一集**：轉寫伺服器有排隊上限、GPU 只有一張、響度正規化是兩趟 CPU 重活 —— 平行不會比較快，只會讓三個瓶頸互相踩。已經有逐字稿的自動跳過分析（整條路上最慢也最花錢的一步）；AI 判讀預設關（慢，而且每一集都要花模型的錢）。**某一集失敗不影響其他集**，錯誤留在那一列上 —— 批次最怕跑到第 4 集掛掉、前 3 集的成果也跟著不見。

23. **專案範本（開場 / 片尾 / 目標響度）**：週更的節目每一集開頭都是同一首開場曲、結尾都是同一首片尾曲、目標響度一樣、修聲設定一樣 —— 現在每一集都要從頭做一遍。工具列「專案範本」把這一集的**跨集重複部分**存成範本（開場 / 片尾 / 固定音效、目標 LUFS、激進度、修聲），下一集開好檔按一下「套用到這一集」就位。
   **只存跨集會重複的東西**：剪輯決策、候選、逐字稿都不存 —— 那是這一集的內容，跨集重用毫無意義而且危險。閃避的音量控制點也不帶（那是針對上一集的人聲算出來的）。
   **片尾曲錨在結尾不是絕對時間**：這是範本唯一真正難的地方。開場曲固定在 0 秒沒問題，但每一集長度都不同，片尾曲存絕對時間的話，套到短的一集會掉在節目結束之後、套到長的一集會壓在中間。所以存的是「距離結尾多久」，套用時才換算。猜錯的代價不對稱（開場曲被當成片尾曲會整個跑掉，反過來只是位置差一點），所以判定門檻抓緊：**落在後半、而且結尾貼著節目結尾**才算片尾。整批套用算**一筆 undo**，套錯按一次 Ctrl+Z 就全收回。來源檔還沒加進媒體清單的段落會**回報數量**而不是靜靜少一段。

24. **講者標籤（誰在講）**：多人 podcast 剪起來最缺的一件事是逐字稿上看不出**是誰在講** —— 於是「只看主持人講的話」「來賓的口頭禪剪掉、主持人的留著」「這一集誰講太多」全都做不到。現在逐字稿每一句左邊有講者色條，換人的那一句寫出名字（每一列都掛一次「Mark：」是雜訊，要一眼看出來的是「這裡換人了」）；工具列「講者」面板列出每個人講了多久、佔比、幾次發言、最長一段。
   **這是算出來的不是猜的**：一人一軌的素材用「同步麥克風」合併時順便指派 —— 每支麥都收得到別人的聲音，但**自己的麥一定最大聲**，所以「這一格誰的麥最大聲」就是「誰在講」。要求領先第二名 6 dB 才指派，兩個人同時講的地方**不指派給任何人**（沒有答案好過錯誤答案）。合併是最後一個「每支麥還分得開」的時刻，這一步不做，之後就只剩一軌，誰講的資訊永遠拿不回來。
   **單軌素材不提供自動指派，而且會說清楚為什麼**：那要靠聲紋分群模型，硬猜出來的標籤看起來很像但錯得很安靜 —— 比沒有更糟，因為使用者會信它。單軌請在講者面板新增講者，再選一段時間手動指派。佔比算的是「佔有人在講的時間」不是佔整集長度（靜音不屬於任何人）。指派錯了 Ctrl+Z 收得回來，改好的名字重跑指派也不會被打回檔名。

25. **字幕與逐字稿匯出（SRT / WebVTT / Markdown / 純文字）**：上架 YouTube 要字幕、部落格要逐字稿、無障礙要文字檔 —— 工具列「字幕與逐字稿」選格式、看預覽、存檔或複製，有講者標籤時可以把名字寫進去。
   **這裡真正難的不是格式，是時間。** 逐字稿在**來源時間軸**上，字幕要的是**成品時間**：剪掉 20 個贅字之後，來源 12:30 那句話在成品裡是 12:11，剪愈多錯愈遠 —— 而且錯得很安靜，字幕會整份慢慢飄掉，愈後面愈離譜。所以每一則的時間都經過 `mapSrcToOut`，而**被剪掉的字整個不出現**（不是往前挪，是根本沒說過）。
   斷句也有講究：換講者一定另起一則（一則字幕混兩個人的話是不能讀的）、剪掉一大段（>700 ms）的兩邊要斷開但**剪一個贅字不打碎句子**、字數上限用**顯示寬度**算（中文一格算兩格，不然 21 個中文字會被當成還能再塞 21 個）。輸出前再修一次：太短的拉長到看得完，但**不可以吃到下一則**——字幕重疊時多數播放器會疊著畫或乾脆丟掉一則。

26. **依講者篩選（只看某個人 / 只清某個人的口頭禪）**：講者標籤真正的用處在這裡。逐字稿上方多一排講者 chip，點一下就**只看那個人講的話**；「贅字管理」也有同一排，選了之後統計與「全剪 / 全留」都只動到那個人的那幾筆。
   **主持人的「對」跟來賓的「就是」不該用同一個決定** —— 主持人的附和多半是在給回饋，整群剪掉會讓對話聽起來很冷淡；要清的是來賓的填充詞。
   篩選**只影響看得到什麼，不影響剪輯**：留著的句子時間戳還是原本的，點下去照樣跳到音檔那個位置，也不會因為被篩掉就變成被剪掉。跨在換人邊界上的候選歸給**重疊最久**的那個人；判不出是誰的（兩個人同時講）在篩選時排除 —— 不確定是誰的，不該因為「篩了主持人」就被整群剪掉。篩選列放在空狀態**外面**：篩到一個沒有贅字的人時，如果連篩選列也跟著消失，就回不去「全部人」了。

27. **講者感知的逐段平衡**：講者標籤不只用來顯示，輸出時的響度平衡也吃它。
   逐段平衡有兩個保護機制：相鄰段落 3 dB 的階差限制，以及 3-tap 平滑。它們存在的理由是「同一個聲音不該忽大忽小」—— 那是聽得出來的抽動。但**兩個不同的人本來就是兩個不同的音源**：來賓比主持人小 6 dB 是要一次補起來的，慢慢爬上去只會讓每一次換人之後的頭幾秒都還在錯的音量上，而在一來一往的對話裡，那就是整集的大部分。平滑更糟：它會把前一個人的增益直接混 25% 進來，等於拿別人的音量來校正這個人。
   有講者標籤時，這兩個機制**不跨過換人的地方**。實測（同一個保留段內四個單元，前兩個主持人 −20、後兩個來賓 −30，目標 −20）：沒有講者標籤是 `[0, +2, +5, +8]` —— 來賓要爬兩格才到位，而且主持人明明已經在目標上卻被拉高 2 dB；有講者標籤是 `[0, 0, +8, +8]`。判不出講者的單元（兩個人同時講）當成延續，不會憑猜測製造音量跳點。
   講者面板同時列出**每個人的來源響度**（BS.1770 閘門積分，把那個人散在整集各處的發言收集起來一起算，不是先算每段再平均）與落差判讀：3 dB 以內聽不太出來、3–6 dB 補得動、超過 6 dB 就直說「這不是後製能好好補救的，下次把兩支麥的增益調近一點」—— 把小聲的那一位拉起來，他的底噪與房間聲會一起拉起來。發言少於 5 秒的人不給數字（三秒鐘的附和算出來的響度不能拿來做任何決定）。

28. **依章節分割輸出（一次錄多集）**：一次錄三集、把一場長訪談切成上下集、把贊助口播單獨輸出一個檔 —— 章節標記本來就標好了，那就是分割點。工具列「依章節分割輸出」列出會切成幾段、每段成品多長、檔名叫什麼，選個資料夾就一次跑完。
   **每一段各走一次完整的輸出管線**（逐段平衡、修聲、配樂、響度正規化），不是把成品切開：切成品的話每一段的響度都是照整集算的，單獨聽會偏掉，切點也會落在樣本中間。實測 wav 輸出每一段的長度與計畫**差 0 毫秒**（mp3 會多約 40 ms，那是 mp3 的框架填充，整集一次輸出也一樣）。
   細節都是會咬人的那些：第一個章節不在 0 秒時**自動補一段開頭**（不補的話那段話會安靜地不見）；章節標題是使用者打的，`/`、`:`、`?` 一律洗掉（不洗會寫到別的目錄去），Windows 保留裝置名（CON、NUL…）與結尾的點也擋掉，撞名的加流水號；整段都被剪掉的段落丟掉而且編號重新連續；**一次跑一段**（響度正規化是兩趟 CPU 重活），某一段失敗不影響其他段。

29. **發布包（一次把上架要用的東西產齊）**：音檔、字幕、逐字稿、節目筆記、章節清單這五樣這個 App 全都做得出來，但分散在五個對話框裡 —— 每週都要開五次、存五次、自己想檔名、自己收進同一個資料夾。工具列「發布包」選個資料夾就用**同一個前綴**一次產齊，外加一份 `-README.md` 說明這一包有什麼。
   **上架前最常出的錯不是做不出來，是「少帶了一個」。** 所以沒帶到的項目也會列在清單上並寫原因（沒有逐字稿就沒有字幕、沒產節目筆記就沒有筆記），用刪除線標出來 —— 不會安靜地少一個檔案。清單裡還有成品長度、**輸出後實際量到的響度**、講者佔比、章節時間表，以及交付前檢查的結果，所以三個月後翻出這個資料夾，光看那份 README 就知道這一包是什麼、少了什麼、能不能直接上架。
   `-chapters.txt` 是給 YouTube 說明欄 / Apple Podcasts 貼上用的純文字時間表，第一個章節不在 0:00 時會自動補一行（YouTube 的規矩，不補整份章節都不生效）。檔名前綴照樣會洗掉不能當檔名的字元。**交付前檢查有擋下項目時仍然照產**，只是寫進清單並回報 —— 擋下來反而讓人沒辦法先產一份給自己聽，決定要不要上架的是人。

30. **輸出後的響度驗收（而且會說「為什麼沒打到」）**：輸出完成後不只印一個數字，而是判定有沒有達標（±0.5 LU 內達標、±1.5 內警告、再多就是未達標），真實峰值也一起看，並且在**沒打到目標時說明原因**。
   這件事重要在於：**最常見的沒打到不是 bug，是物理限制**。來源整體很小聲但有幾個很尖的峰時，要拉到目標響度就會超過真實峰值上限，loudnorm 只好少拉一點。實測這個 App 自己的樣本：目標 −16、輸出 −17.3 LUFS、真實峰值 **剛好貼在 −1.5 dBTP 上限**——工具一直都是對的，只是從來沒說。只顯示「−17.3 LUFS」而不解釋，使用者會以為工具壞了，然後去改一個改不動的設定。
   分得出來的依據是「偏小聲**而且**峰值貼著上限」→ 是上限擋住的；峰值還有空間的偏小聲則是另一回事（那多半是這一集大部分時間都很安靜，或逐段平衡被關掉），不會都推給上限。判定與原因同時出現在輸出對話框與發布包的 `-README.md` 裡。
   **還會告訴你成品有沒有被動態壓縮過**（而且看的是實際編碼那一趟，不是量測那一趟的預估 —— 兩趟的目標可能不一樣）。 輸出送給 ffmpeg 的是 `linear=true`（只套一個增益、不改動態），但那只是「請求」—— 需要的增益會讓峰值超過上限時，ffmpeg 會**自己退回 dynamic**，也就是動態壓縮，成品的音量起伏被壓平。它只在 loudnorm 的 JSON 裡講一次 `normalization_type`，不解析就永遠不知道自己交出去的是壓過的檔案。實測這個 App 自己的樣本：**一直都是 `dynamic`**。

31. **保留動態（寧可小聲也不壓）**：輸出時多一個開關。不開的話遇到拉不到目標就讓 ffmpeg 自己退回動態壓縮（v0.74 之後那件事會被明確回報）；開了就**把目標降到不需要壓縮就拿得到的位置**，成品小聲一點但音量起伏完整保留。訪談、有音樂的節目、或單純不想被壓的時候用。
   會不會被壓有**兩個**條件，兩個都得滿足才會留在線性增益，而且都是實測出來的：
   - **響度目標要拿得到**：極限是 `來源響度 + (峰值上限 − 來源峰值)`（純增益把響度與峰值平移同樣的量）。實測界線是硬的 —— 來源 −17.45 LUFS / −0.49 dBTP、上限 −1.5 → 極限 −18.46：目標 −18.46 回 `linear`、−18.4 就變 `dynamic`，差 0.06 dB 換一種處理。所以夾的時候會留 0.5 LU 餘裕。
   - **不要約束動態範圍**：量到的 loudness range 超過請求的 LRA 時，loudnorm 一律退回 dynamic，跟目標拉不拉得到無關（請求 11 / 量到 8 → linear；請求 11 / 量到 12 → dynamic；請求 2 / 量到 2.8 → dynamic）。所以這個模式會把請求的 LRA 開到最大。

32. **重錄偵測（講錯了說「重講」，前面那次跟著剪掉）**：一個人錄音沒有導播喊卡，講壞了就是當場說一聲再講一次。剪的時候要做的事很機械：找到那句「重講」，把它前面那次失敗的嘗試連同這句指令一起拿掉。現在規則層會自己提出來 —— 理由寫得很清楚（「聽起來是重錄：『重講』，連同前一句『啊講錯了』一起剪」），你只要看一眼決定接不接受。
   **只建議，永不自動剪。** 這條跟其他規則不一樣：別的規則剪的是贅字、停頓這些「拿掉也不會少講什麼」的東西，這一條剪的是**一整句真正的內容**。判斷錯的代價完全不對稱 —— 少剪一句只是留個瑕疵，多剪一句是內容不見了。
   精準度靠三個條件：指令詞要在句子**開頭**（「重來一次」是指令，「我覺得我們可以重來一次」是內容）、指令句要**短**（真的在下指令的人不會講一長串）、前面**要有東西可以重錄**（第一句就說「重講」時只剪指令本身）。前一句離太遠（>30 秒）也不連著剪，那多半已經是別的內容了。

33. **選取範圍的響度讀數**：在波形上拉一段，狀態列的響度表旁邊多一個「選取 −32.1 (+1.9)」。
   **重點是括號裡那個差距，不是絕對值。** 剪的時候會問的是「來賓這段是不是比整集小聲」——
   一個 −32 LUFS 的數字本身回答不了那個問題，要跟整集比才知道。實測這個 App 自己的樣本：前半段 −32.1（比整集大 1.9 LU）、後半段 −37.5（小 3.5 LU），同一段錄音裡差了 5.4 LU。
   算法跟整集基準用同一支（能量平均、跳過靜音），兩邊定義一致才比得起來。

34. **波形上的講者色帶與換人導覽**：波形下緣一條窄色帶，誰在講就是誰的顏色；`Alt+Shift+[` / `]` 跳到上 / 下一個換人處（會順便說換到誰）。
   逐字稿上本來就看得到講者，但那要捲到那一句才知道。在**波形上**最想一眼看到的是「這一集的節奏長什麼樣」—— 誰講得久、哪裡是一來一往、哪裡是一個人講了八分鐘。那是一條色帶就能回答、逐字稿回答不了的問題。
   兩個刻意的決定：**沒指派到的地方留白**（留白就是「這裡沒人在講或分不出是誰」，用前一個人的顏色補滿會讓人誤以為那段是他講的）；**太窄的段落至少畫 1px**（40 分鐘縮到整頁時一句「對」只有 0.3px，四捨五入就消失，但那正是一來一往的節奏，全沒了色帶就只剩兩塊大色塊，看起來像沒在互動）。跳換人處時抓的是**段落起點**不是上一段結尾 —— 中間可能有沉默，跳到結尾會落在沒人講話的地方。

35. **吸附指示（吸到哪裡、吸到什麼）**：拖一刀、拉選取、下標記的時候，位置會被吸到最近的拍點 / 接縫 / 標記 / 句界 / 字界 —— 這件事一直都在發生，但**畫面上完全沒有交代**，使用者只會覺得「我明明放在這裡」。現在吸附時會畫一條線並標出吸到的是哪一類，停一下自己消失。
   **標出「吸到什麼」而不只是畫線**：吸到「句界」跟吸到「拍點」是兩種完全不同的意圖，吸錯的時候要看得出來是哪一類在作怪，才知道要關掉哪一個吸附來源。實測：把時間點放在某句話開頭後 30 ms，結果被吸到 12 ms 外的**接縫**而不是句界 —— 沒有標籤的話這件事永遠不會被發現。

語音辨識、人聲分離與音樂生成由自架的 [ttls](https://ttls.markkulab.net/)（Seal-TTS REST；`/v1/transcribe` = faster-whisper large-v3 逐字時間戳、`/v1/separate` = demucs htdemucs、`/v1/music` = ACE-Step）提供。

36. **聲音體檢（逐字稿看不出來的毛病）**：這個 App 的判斷幾乎都建立在**文字**上 —— 哪句是贅字、哪裡重講、章節切在哪。但把節目搞砸的常常是文字完全看不到的東西：前級開太大整段削波、麥克風被撞了一下之後音量差 9 LU、錄音介面有直流偏移、剪完之後中間留了 12 秒空白。這些要「聽過整集」才會發現，而剪的人通常是跳著聽的。
   輸出對話框的「輸出前檢查」現在會一起報這四種，**每一條都能點「去聽 12:30」直接跳過去**（光給一個數字沒有用）。資料來自開檔時就算好的本機分析（每 5 ms 一個 min/max/RMS、每 100 ms 一個響度視窗），**不需要重新解碼音檔**，掃 57 分鐘是 1 毫秒的事。
   > **只講量到的事實。** 峰值資料是量化成 i8 的，證明不了「確定削波」，所以寫的是「波形打到滿刻度、連續幾毫秒」，判斷留給人。同理，沒有本機分析時回的是 **null 而不是零** —— 「沒檢查」跟「檢查過很乾淨」是兩件事，不能讓前者被講成後者。
   > **一條都不擋輸出。** 剪的人常常就是要先輸出一個半成品去聽，跳出來擋住是最惹人厭的一種貼心。
   > 已經被剪掉的段落不報（削波在剪掉的地方就不是問題，長停頓被剪掉正是它該有的下場）；從靜音進到說話不算音量突變（那是正常的）；音量突變的位置取**相鄰視窗落差最大**的那一格 —— 用「第一個超過門檻的視窗」會早 0.4 秒，那會讓人點下去聽到變化之前的那一段，以為報錯了。
   > 驗證方式是拿真實錄音**故意弄壞**再掃：8–12 秒 +25 dB、12–20 秒 −12 dB、20–26 秒接一段全靜音、整份 +0.08 直流偏移，四種都要被抓到而且位置對得上；同一份錄音沒動過的時候一條都不能報。

37. **替代 take（Final Cut 的 Audition）**：一個人錄旁白或 podcast，講壞了最常見的反應**不是**說「等一下重講」——
   那個規則層早就在抓了（第 32 項）。最常見的是：停半秒，然後**把同一句再講一次**，什麼都沒說。
   錄完一集下來，同一句話有兩三個版本散在裡面，而逐字稿上它們看起來就是三句普通的話。
   工具列「替代 take」把每一組並排列出來，每一次都能單獨試聽，挑一個留下、其餘一次剪掉（一次 undo 就全還原）。
   > 判斷「同一句」用的是**字元**層級的編輯距離，不是詞：中文沒有空白分詞，而重錄常常只差一兩個字
   > （「這個功能很好用」→「這個功能非常好用」），用詞比會判成兩句不同的話。
   > 只比**時間上相鄰**的幾句（預設往後三句、間隔 20 秒內）—— 同一個詞在整集裡重複出現是正常的，那是主題，不是重錄。
   > 太短的句子不算（「對」「好」「是啊」重複出現是講話的常態）。
   > **預設留最後一次**（會再講一遍就是因為前面那次不滿意），但那只是預設值：有時候第一次講得最自然、後面越講越僵，
   > 所以按鈕上寫的是「留這次」而不是「接受建議」。
   > 這裡剪掉的是**一整句真正的內容**，不是贅字 —— 所以只找不剪、索引超出範圍時什麼都不做（不會把整組剪光）。
   > 地端 claude 也有這兩支工具（`list_takes` / `keep_take`）。

38. **音軌的剪下 / 複製 / 貼上 / 搬移**：`Ctrl+X` 剪下選取、`Ctrl+C` 複製、`Ctrl+V` 貼到播放線、`Ctrl+Shift+V` 把選取搬過去。
   這是這個 App 第一個讓**成品順序可以跟來源不一樣**的功能 —— 在此之前，剪輯只能「拿掉東西」，不能重排或重複。
   > **剪貼簿只存一段來源範圍（起訖時間），不存音訊本身。** 所以複製十分鐘的內容是零成本的；
   > 但也因此，貼上之後如果又去修剪原本那一段，貼上的那一份**不會**跟著變（它記的是時間，不是內容）。
   > **貼上的位置錨在來源時間**，不是成品時間：之後多剪掉幾個贅字，貼上的那塊會跟著它前面那句話走。
   > （配樂 overlay 剛好相反，用的是成品時間 —— 配樂要對齊的是聽眾聽到的時間點。）
   > **只能貼回同一個音檔**：貼上記的是「來源檔的哪一段」，跨檔案貼上要的是另一個來源，那是多軌的事。與其做出一個會安靜貼錯內容的東西，不如明講不支援。
   > 播放線落在選取範圍**裡面**時搬移不做事 —— 那等於搬到自己身上，安靜地做一件沒有意義的事比擋下來更糟。
   > 內部是把 keeps 從「來源順序」變成「**成品順序**」（`analysis/edl/arrange.ts`）。Rust 完全不用改：`RenderSeg` 本來就只是一串照順序接起來的來源區間。
   > 而 `mapSrcToOut` 會自己認出重排並改走順序感知的查表 —— 沒認出來的話，字幕會整份慢慢飄掉、章節跳到不對的地方，而且**不會有任何錯誤訊息**。

37. **找得到功能：命令面板、右鍵子選單、不灰掉要解釋**：功能一多，最常見的問題不是不會用，是找不到在哪。現在 `Ctrl+K` 打字就搜（翻譯後的名字、繁中原文、英文關鍵字、快捷鍵都比得到）；波形上選一段按右鍵，「效果 ▸ / 修復 ▸」子選單裡就是能對這一段做的事；工具列只留五顆主要動作（開檔 / 分析 / 輸出 / 一鍵智慧剪輯 / 儲存），其餘收進「AI 與交付 ▾」「更多 ▾」。
   **不能做的功能不會灰掉不講**：工具列 tooltip、右鍵、命令面板右側寫的是同一句原因（「先在波形上拖一段」「先完成分析」），按下去也是 toast 那句話，而不是沒反應。
   > 這一切背後是一張指令表（`src/commands/`）：一個功能只寫一次，快捷鍵說明、工具列、右鍵、命令面板全部從它長出來。以前是 22 個 boolean、41 個 props 加一張手抄的快捷鍵表，漏掉 Alt+X、Shift+I/O 這種事沒人發現。順手修了一個中文輸入法下 `Shift+S`（滑聽）永遠按不到的 bug。

38. **簡易 / 專業雙模式（小白也能用）**：第一次裝好打開是**簡易模式**：開始畫面先問「你想做什麼？」（剪 Podcast / 把雜音去掉 / 剪音樂…），開檔之後右邊只有幾顆白話按鈕 —— 自動剪掉贅字、去雜音、音量弄整齊、剪掉選的這段、只留選的這段、加片頭 / 片尾音樂、輸出 mp3 —— 最上面永遠是「復原」，每個會改到聲音的動作做完都會跳一句話加一顆復原鈕（小白不知道 Ctrl+Z）。波形上拖一段按右鍵是平的七項白話選單，沒有子選單；傳輸列只剩播放、時間、縮放滑桿、循環。右上角一鍵切到**專業模式**看到完整介面（側欄、精準修剪、快捷鍵、命令面板），檔案、剪輯、選取都還在。
   **兩邊是同一套指令、同一個波形**（`SimpleShell` / `ProShell` 掛的都是 `Workspace` + `TranscriptArea`），簡易只是拿掉東西，不是另一個 App；升級前就在用的人打開還是專業模式，不會被丟進簡易。
   > 小白驗收是用 CDP 跑真的介面：開檔 → 去雜音 → 拖一段右鍵剪掉（按 toast 的復原）→ 輸出 mp3，全程只用面板按鈕與右鍵、零快捷鍵，八次點擊。

39. **效果不只四種了：峰值正規化、響度對齊、淡入曲線、反相、噪音樣本**（GoldWave 的 Maximize / Match Volume / Fade / Invert / Noise print 那一組）：以前選一段能做的只有靜音、增益 ±dB、淡入、淡出。現在「效果 ▸」裡多了**峰值正規化**（把這段最大聲拉到 −1 dBFS，簡易模式叫「音量拉滿」）、**響度對齊**（這段比整集大 / 小幾 LU 就補回來，或指定 −16 LUFS）、**淡入淡出**可以選長度與曲線（線性 / 等功率 / 指數）、**反相**；「修復 ▸」多了**把這段當噪音樣本** —— 選一段 0.3–5 秒沒人講話的純底噪，之後「去雜音」的底噪值就以它為準，不再用整檔 5% 百分位猜。
   > 這一輪**零 Rust 濾波**：峰值正規化與響度對齊都是從已經有的 analysis.bin（5 ms 桶的 i8 峰值 / u8 RMS）算出「該加幾 dB」，結果就是一個普通的增益效果 —— 所以能 undo、能存專案、CLI 也認得。代價是**量化誠實**：i8 在 −30 dBFS 的誤差已經 ±1.1 dB，所以太小聲的段落（峰值 q < 8）對話框會寫「這段太小聲，分析解析度不夠」並改建議響度對齊，而不是印一個看起來很準的數字。
   > 噪音樣本會檢查「像不像純底噪」：p95 − p5 超過 12 dB 就拒絕並說「這段裡好像有講話」。太短 / 太長也會說原因，不是灰掉。
   > 反相與淡入曲線是 Rust 端 `render.rs` 逐 frame 相乘的同一套包絡，TS 與 Rust 用同一張樣本表釘死（`{p: 0, .25, .5, .75, 1}`），未知的 shape / kind 在輸出前就報錯，不再默默當 1。降噪 / 去爆音 / 去嗡聲 / EQ 這類要真的濾波的效果，資料模型這一輪先進去（`RangeEffectKind`），引擎下一輪。地端 claude 多了 `normalize_selection` / `set_noise_print` 兩支工具；CLI 遇到範圍濾波效果會印「⚠ 這個專案有 N 段輸出時套用的效果，CLI 不會處理」而不是默默少掉。

40. **範圍濾波：選一段 → 降噪 / 去爆音 / 去削波 / 去嗡聲 / DC，真的只處理那一段**：修聲以前是整集一起（輸出時整條套 afftdn），現在「修復 ▸」裡的五種都是**範圍**效果 —— 在波形上拖一段、右鍵、套用，色塊留在時間軸上，輸出時才處理。簡易模式右鍵的「去雜音」有選取就走這條（沒選就退回整集）。對話框有 A/B 試聽：對來源檔直接切那一段做 dry / wet，15 秒的段不到 1 秒就能聽，不用等剪接器從頭剪到那裡。
   > 引擎是 Rust 的串流 punch-in（`src-tauri/src/fx.rs`）：剪好的成品逐 frame 往前讀，遇到效果區域就開一個小 ffmpeg 子程序只處理那一段（多帶 250 ms–1 s 的 pre-roll 讓濾鏡暖機），丟掉暖機與濾鏡延遲的 frame，再用 10 ms 交叉混回去；兩段相接時是 wet→wet 交叉，dry 不會漏進縫裡。寫出的 frame 數永遠等於讀進來的 —— 效果不動時鐘，字幕 / 章節 / 驗收全部不受影響。
   > 為什麼不用一條 `enable='between(t,a,b)'` 的大 filter_complex：`acompressor / aecho / areverse / atempo` 沒有 timeline 旗標；每個 AVFrame（~21 ms）硬切開關會 click；afftdn 內容延遲 25 ms 但 pts 不延遲，邊界會出現重複與空洞。濾鏡延遲用 1 kHz tone burst 互相關校準（`cargo test -- --ignored fx_`），ffmpeg 一換版就重量；wet 回來的長度不對一律報錯，**絕不默默退回未處理**。
   > 效果釘在來源時間、引擎跑在成品時間，換算建在輸出計畫的段落上（`analysis/fx/regions.ts`）：只輸出一段、精華合輯、之後再剪掉前面一個贅字，區域都跟著對；兩種效果疊在同一段會拆成三塊，鏈內順序固定（先 DC、再爆音、再削波、再嗡聲、最後降噪），不管你先加哪一個。地端 claude 有 `list_effects` / `apply_effect`（任何效果都能套、參數省略就用建議值）。

41. **效果選單補齊 + 頻譜視圖 + 嗡聲偵測**（GoldWave 的 Effects 與 Frequency analysis）：「效果 ▸」多了**等化**（三段，預設：人聲清晰 / 溫暖 / 電話 / 去悶）、**壓縮**（人聲 / 廣播）、**回音**、**殘響**（多 tap 近似）、**反轉**（倒著播）、**變調**（±12 半音、長度不變）。全部走同一套範圍濾波引擎：選一段、右鍵、A/B 試聽、套用，輸出時才處理。反轉 / 變調之後波形跟原本無關，所以那兩段用等功率交叉混回去、驗收只比位置不比相似度；反轉的 pre-roll 會反到串流尾巴，引擎對它另有一套 roll plan（測試釘住）。
   > **頻譜視圖**：「更多 ▾ → 波形 / 頻譜 / 疊合」切換。不預算整檔的頻譜（固定 hop 撐不了縮到 2 秒的視窗、一小時多 16 MB），也不用 wavesurfer 的 spectrogram 插件（要在瀏覽器把整檔解成 PCM）—— 畫面看哪一段就叫 ffmpeg `showspectrumpic` 出哪一段的 PNG（log 頻率軸、60 dB 動態、深色 magma / 淺色 viridis），捲動時前一張先跟著位移，150 ms 沒再動才要新的；同一個視窗量化到 1/8 格，小幅捲動命中同一張快取。波形在頻譜模式用 `::part(canvases)` 壓淡，兩層疊著看。
   > **嗡聲偵測**：「去嗡聲」對話框一開就對選取解一段（≤ 30 秒）算平均功率譜（純 Rust radix-2 FFT，16384 點、Hann），在 50 / 60 Hz 與諧波找「比附近中位數高 12 dB 以上」的峰，至少三個諧波排成一列才算電源嗡聲，然後把基頻與該挖幾個諧波直接填進參數。量不到就明講「沒有偵測到明顯的電源嗡聲」，不會硬填。

42. **七種輸出格式 + 轉檔 / 批次轉檔 / 從影片抽聲軌 + 合併檔案**（GoldWave 的 File Merger / Batch Processing）：輸出多了 **FLAC / OGG / Opus / AIFF**，無損的可以選 16 / 24 / 32-bit。格式表只有一份（`src/analysis/formats.ts` ↔ Rust `formats.rs`，codec 字串 golden 互相釘死）—— 以前 `"mp3" | "m4a" | "wav"` 散在六個地方加三個下拉，不認得的格式會**默默出 mp3**；現在選了 flac 就拿到 flac，或拿到一句錯誤。章節只有 mp3 / m4a 寫得進去，輸出到別的格式會跳一句「這個格式寫不進：章節（成品裡沒有）」，不會默默少掉。
   > **轉檔・抽聲軌**（開始畫面那張卡、或「更多 ▾ → 轉檔」）：幾個檔一起選就是批次，影片（mp4 / mkv / mov / webm…）直接丟進來只拿聲音。能直接複製就不重新編碼 —— mp4 裡的 aac → m4a、mkv 裡的 opus → opus 是零損失、幾百毫秒；勾了「正規化到 −16 LUFS」才會走 loudnorm 兩趟線性（跟輸出同一條）。逐檔序列跑、一個壞檔不讓整批停，結果表寫每一檔是複製還是轉碼、沒帶到什麼。
   > **合併檔案**：幾個音檔照順序接成一個，留白或交越（交越用與 EDL 同一條夾限，短檔不會被吃光），「拉到同一響度」用各檔分析過的 LUFS 補差。輸出 48k 24-bit wav 放在第一個檔旁邊、加進媒體清單，原檔不動。超過 40 個輸入改寫 `-filter_complex_script` 檔，避開 Windows 32 k 命令列上限。
   > 開檔也收影片了（`MEDIA_EXTENSIONS`）：每個 ffmpeg 呼叫本來就 `-vn`，開 mkv 直接看到波形、照剪。

43. **Guide / Dub 時間對齊**（Synchro Arts VocALign 的那件事，只做時間、不做音高）：「工具 → 對齊」選一軌當 Guide（基準）、一軌當 Dub（要扭的），三種用途一個引擎 —— **補錄一句**對回原位（Guide 只看選取的原句）、**多麥時鐘漂移**（兩支錄音機一小時漂兩秒那種）、**疊錄 / 和聲**。分析完給位移、最大偏差、每小時漂多少秒、幾段速率、信心；三車道（Guide / Dub / 對齊後）看得到扭完長什麼樣；**Tightness** 0–100 即時重算不用重跑（0 = 只做整體位移，等於「同步麥克風」；100 = 貼到每個字）。輸出 `_aligned.wav` 加進媒體清單，原檔不動，輸出後自動每 10 秒一段比對殘差，對不上會明講「可能沒對上：先聽第 N 秒那裡」。「同步麥克風」多了一格「同時校正時鐘漂移」，超過 20 分鐘且長度差扣掉位移 > 300 ms 時自動勾。
   > 引擎是**帶狀 DTW 粗→細**（`analysis/align/`）：先用既有的能量互相關拿全域位移，100 ms 一格在 ±1.5–3 秒的帶裡走一次，再 5 ms 一格在粗路徑 ±200 ms 的帶裡走第二次；步型 (1,1)/(1,2)/(2,1) 把局部斜率鎖在 ½–2 之間，回溯只存每格一個 byte（一小時 5 ms ≈ 58 MB，超過上限自動放大 hop）。特徵是 RMS + onset（句子的起頭在兩個 take 裡最一致，DTW 靠它釘在字的開頭）；多麥漂移只用 RMS（串音不同，onset 不可靠）。路徑 → 拉直「兩邊都安靜」的段落（差異吸收在沒人聽的地方）→ tightness 平滑 → Douglas-Peucker 簡化 → 分段固定速率（≥ 250 ms、0.5% 量化、0.5–2 夾限）；去掉直線後殘差 < 20 ms 且斜率離 1 不到 0.2% 就只做一段等速。信心 = DTW 路徑比「整條平移 1.5 秒的路」低多少 × 絕對成本，< 30% 標黃、MCP 拒絕渲染。
   > 渲染在 Rust（`align.rs`）：**單趟、一個 `atempo`、`asendcmd` 驅動** —— `asetnsamples=240` 讓指令落在 5 ms 格線上，指令檔每段一行 `t atempo tempo r;`，避開 asplit fan-out（晚開始的分支會在 FIFO 裡累積整個後半段）與幾百段串接的 32 k 命令列。指令檔放 temp、用安全的檔名並切工作目錄，因為 Windows 路徑的 `:` 與 `\` 在濾鏡語法裡兩個都是分隔字元、跳脫層級一錯就整條鏈解析失敗（第一版真的錯了）。三段速率 0.9 / 1.1 / 1.0 的往返測試：輸出長度 == Σ(len / tempo) ± 20 ms。
   > **不在這一版**：音高（SmartPitch / formant / transpose —— 沒有音高追蹤、LGPL 沒 rubberband）、Sync Points 與 Protected Areas 的畫面操作（引擎已支援保護區、MCP 可傳）、疊錄用的 8 帶分頻特徵（先用能量包絡，長音裡的路徑可能較鬆，對話框會說）。

## 提示詞

四個角色的系統提示詞（剪輯 / 審核 / 節目筆記 / 助手）可以在 App 裡直接改（工具列「提示詞」）。
這些字串就是 AI 的行為本身 —— 判讀鬆緊、審核立場、節目筆記的口氣 —— 寫死在原始碼裡
等於「要調就得改程式再編譯一次」，而提示詞正是最需要反覆試的東西。

每一條都寫清楚**誰在用**、**改壞了會怎樣**；改過的標「已改」，可以還原、可以匯出成 JSON 給別人。
**只存被你改過的那幾條**：全部存下來的話，之後改進了預設值，你的設定檔會把舊版本永遠凍在那裡而且完全無感。

> 輸出語言不用寫進提示詞 —— 那是依節目 / 介面語言在執行期接上去的。

## 長節目

目標尺寸是「一小時的談話節目」，所以是拿那個尺寸量的，不是拿三十秒的樣本量的：
57 分鐘 / 11400 字 / 1140 句 / 4560 個候選。

拖播放線 60 fps、接受一筆候選 0.11 秒、整頁 DOM 節點 772 個。

三份會**跟著節目長度一起長**的清單（逐字稿、候選、時間軸索引）都只畫看得到的那幾列，
所以三小時的錄音跟一小時的成本是一樣的。跟播捲動、鍵盤在候選之間跳、搜尋跳到下一個命中
都不靠 `scrollIntoView`（那一列可能根本不在 DOM 裡），走的是虛擬清單自己的位移。

> 這些數字全部是**開發模式**下量到的（React 的開發期驗證會放大一部分成本），正式版只會更快。
> 量測方式是 CDP：`WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS="--remote-debugging-port=9222"`，
> 從 node 打 `Runtime.evaluate` 造一份真實長度的逐字稿再操作它。

## 需求

- Windows 10/11（macOS / Linux 可自行建置，見 `.github/workflows/release.yml`）
- **ffmpeg**：Windows 安裝檔已內建（LGPL 版，見 [THIRD-PARTY-NOTICES.txt](THIRD-PARTY-NOTICES.txt)），裝好就能用。
  - 你自己裝的優先：解析順序是「設定裡的自訂路徑 → 系統 PATH → 內建 → 常見安裝位置」，狀態列會顯示現在用的是哪一個。
  - macOS / Linux 目前不內建，需自行安裝 [ffmpeg 7+](https://ffmpeg.org/)（deb / rpm 已宣告套件相依）。
  - 從原始碼建置時，內建版靠 `node scripts/fetch-ffmpeg.mjs`（URL 與 sha256 釘在 `scripts/ffmpeg-manifest.json`）；不跑也能開發，只是會退回 PATH。
- ttls API key（設定 → 伺服器；**只存 OS 鑰匙圈，不進任何檔案**）——沒有金鑰也能看波形、手動剪、輸出
- **預設就是本機辨識**（設定 → 逐字稿來源）：同一個 large-v3 跑在自己機器上，不上傳、不需要金鑰。
  App 會偵測 python 與套件是否就緒，沒裝的話**選好模型按一顆鈕就裝**（套件 + 模型一起抓，輸出逐行顯示）。
  按之前會先給你看實際會執行的指令 —— 這一步會動到你的 Python 環境。
  **選模型時會直接告訴你規格與顯存夠不夠**：每個模型列出參數量、顯存（int8）、沒有顯示卡時要多少記憶體、相對速度，
  再拿 `nvidia-smi` 讀到的實際顯示卡去比，寫成「你的 RTX 4060（8.0 GB）跑得動」／「只有 4 GB，還差 1.1 GB」。
  > 顯存標的是 **int8** 的數字，因為這個 App 就是用 int8 跑的（`compute_type="int8"`）。
  > 拿 fp16 的數字來標會害人多買一張卡：large-v3 fp16 要 4.7 GB，int8 只要 3.1 GB。
  > **顯存不夠不會自動改用 CPU**，是直接失敗 —— 所以不夠的時候寫的是「會失敗，請改選小一點的」，不是「會比較慢」。
  > 數字是估計值（錨在 faster-whisper 自己的 benchmark：large-v2 GPU int8 ≈ 3091 MB，其餘依參數量往下推），畫面上照實說明。
  > 順帶修掉一個會踩到的預設值：辨識模型的預設是 `auto`，那是 ttls 伺服器的概念；本機這條路會把字串直接當模型名餵給
  > faster-whisper，於是「把來源切到本機、其他都不動」的人會拿到「去下載一個叫 auto 的模型」然後失敗。
  > 現在 `auto` 在本機是有意義的：**依你的顯存自己挑**一個跑得動的。
  輸出格式與 ttls 相同，所以規則層拿到的訊號一模一樣（字級時間戳、no_speech、avg_logprob、compression_ratio）。
- 選用：[Claude Code](https://claude.com/claude-code) CLI 已登入（AI 判讀 / AI 助手；預設模型 sonnet，可在設定改）

## 使用

第一次打開是**簡易模式**（開始畫面問你想做什麼、右邊幾顆白話按鈕），右上角可以切到專業模式。以下是專業模式的流程。

畫面最上方的流程列會告訴你現在在哪一步、下一步按什麼：**① 開啟音檔 → ② 分析 → ③ 檢視決策 → ④ 輸出**。

1. 開啟音檔（或拖進視窗）→ 幾秒內看到整段波形、時間尺；已可播放、縮放（Ctrl+滾輪 / `Ctrl+=` `-` `0`）。
2. **手動剪**（隨時可做）：按 `S` 切到「選取」工具，在波形上拖一段 → 右下動作列或右鍵：播放（Space，可循環）、剪掉（Delete）、只保留、靜音、淡入 / 淡出、增益、縮放到選取（Z）。`V` 回到「定位」。
3. **分析**：轉檔上傳 ttls 轉寫、規則層提候選（贅字 / 口吃 / 長停頓 / 含糊 / 雜音）。缺金鑰時會直接帶你到設定欄位，不會白白上傳。
4. 看決策面板：綠勾接受、叉拒絕；滑桿調激進度即時重算；`[` `]` 上下一筆、`A` / `R`、`P` 預聽；波形上拖色塊邊緣調整範圍、雙擊切換。
5. **AI 判讀**：Claude 逐段審核候選（apply / suggest / drop），新增含糊 / 離題建議。
6. **AI 助手**：用自然語言指揮（會顯示每個工具呼叫）。
6b. **逐字稿搜尋**：`Ctrl+F` 找字 → `Enter` 逐個跳 → 「全部剪掉（N）」把整集的口頭禪一次處理掉（一次 undo 全還原）。
6c. **修聲**：右鍵「修復 ▸ 修聲…」（或 Ctrl+K 打「修聲」）→ 看量到的底噪 → 用建議值或自己調 → A/B 試聽同一段的原始與修聲後 → 套用。
7. **輸出**：選格式 / 目標響度 / 是否逐段平衡 → mp3 / m4a / wav。效果（靜音 / 淡入淡出 / 增益）與修聲一併套用。
7b. **ASR 驗收**：輸出完成後按「用 ASR 驗收」（或流程列第 ④ 步），成品會被重新轉寫並逐字比對；報告列出漏字 / 該剪沒剪 / 可疑接縫，每筆都能「聽」或「去修」。
8. **去人聲**：工具列「去人聲」→ 選 2 軌或 4 軌 → 各軌寫在來源旁邊並加入媒體清單。

專案存成 `*.aicut.json`（含逐字稿、候選、決策、效果、AI 判讀快取）；同一個音檔重開會沿用快取，不重跑 ASR。`F1` 看完整快捷鍵；`Ctrl+K` 搜任何功能。

> 中文輸入法開著時字母快捷鍵會被輸入法接走，切到英數模式即可；所有動作也都有按鈕與右鍵。

```bash
node dist-cli/aicut.mjs beats song.mp3                                     # BPM / 拍點（--bars 列小節線）
node dist-cli/aicut.mjs music "lofi hip hop, warm" --duration 30 --bpm 90  # AI 配樂（ACE-Step，--quality fast|fine|max）
node dist-cli/aicut.mjs style song.mp3 "acoustic guitar" --from 30 --to 60   # 曲風轉換（--strength 貼近度 0–1）
node dist-cli/aicut.mjs verify ep12.m4a ep12_cut.mp3                       # ASR 驗收（有漏字 / 該剪沒剪 → exit code 2，可接 CI）
```

金鑰：`--key`、環境變數 `AICUT_TTLS_API_KEY`、或專案根目錄 `.env.local`；不會印出、不寫進任何輸出。

**CLI 與 App 的差別**（`cut --project` 會逐項提醒，不會安靜地少東西）：CLI 的剪接器是 ffmpeg 的 `atrim` + `concat`，所以只做全域 loudnorm（沒有逐段平衡）、**不會混入配樂 / 音效**、**不會寫章節**。專案裡有這些東西時 CLI 會出聲說它跳過了什麼；需要完整成品請用 App 輸出。切點、手動剪輯、效果與決策則完全沿用。
